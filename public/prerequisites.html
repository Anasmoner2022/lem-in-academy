Start here: prerequisites and workspace

Bring basic programming experience, including variables, functions, conditions and loops, plus files, terminal use and Git. JavaScript and HTML familiarity are useful background, but no Go, graph algorithms, flow theory or scheduling knowledge is assumed.

Before P01

  1. Be able to create a folder, edit a text file, run a terminal command and describe its exit status.
  2. Use Git to commit a small change and inspect a diff. Keep exercises in separate directories.
  3. Explain a loop and a function returning a value in any familiar language. If those are unfamiliar, take a basic programming bridge before this track; its duration is not included in the estimates.

Required tools

Install a supported Go toolchain that understands Go 1.22 or newer, on a 64-bit target. The supplied modules declare Go 1.22 to use a conservative API baseline; the hub's local validation records the actual installed version. Use a text editor, terminal and ZIP extractor. No external Go modules are required.

go version
go env GOOS GOARCH
go test ./...
go vet ./...

Run each starter's commands inside its extracted directory containing go.mod. The academy root is a different module for publication tooling. Keep student changes outside the generated public/downloads folder so rebuilds cannot overwrite them.

Learning map

P01 teaches Go foundations. P02/P03 teach file and grammar boundaries. P04/P05 teach graphs and BFS. P06 teaches turn invariants. P07 introduces traffic and allocation. P08/P09/P10 teach every new optimization concept before integration. P11/P12 teach adversarial evidence and bounded release. P13/P14 introduce bonus-only stream and raster skills after the core build.

Commands across platforms

Go commands are the same across platforms. A built executable uses ./lem-in on Unix and .\lem-in.exe in PowerShell. Avoid assuming shell redirection/pipelines preserve UTF-8 bytes identically across PowerShell versions; use the Go os/exec harness for byte-exact pipeline tests. The final CLI still requires the file argument upstream requests.

How to use a guide

Read mandatory sections first, trace the self-checks by hand, download the unfinished starter, implement one component and enable its acceptance tests. Add failure tests, run the verification cases and answer the engineering prompts aloud with a reviewer. Completing a reading page does not establish project readiness.
