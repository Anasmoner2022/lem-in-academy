GO ONLY · STANDARD LIBRARY

Exact academy contract

U identifies upstream requirements; A identifies academy decisions resolving unspecified details. Review these policies with the institution before using this curriculum for a formal external audit. These decisions are part of the academy exercises and independently testable.

U · Required behavior

Use Go and only standard packages. Read the colony from one file argument, send n ants from start to end in the fewest movement turns, respect ordinary room capacity one and undirected tunnel capacity one per turn, and print accepted input followed by L-number/destination movement tokens. Names need not be numbers; coordinates are ints. Ignore unknown commands. Malformed data and no-route inputs require the invalid-data error prefix.

A · Input transport and echo

  • Read at most 1 MiB and 4096 bytes per physical line, excluding its line terminator. Accept LF/CRLF; reject bare CR and NUL. A final newline is optional.
  • Normalize CRLF to LF and append one final LF if missing. Preserve other accepted line bytes, including comments, unknown commands and surrounding whitespace. A valid colony has no blank data lines, so exactly one blank line separates echo from moves.
  • Classification uses trimmed line text; room fields use whitespace separation. The normalized original text, not regenerated structs, supplies the success echo.

A · Grammar and terminal state machine

  • Phases are count, rooms, links. Comments begin with # after surrounding whitespace is trimmed. Exact ##start/##end are known commands; any other ## line is ignored semantically. Other # lines are comments. Unknown commands may occur in any phase.
  • Count is decimal [1-9][0-9]* in 1..10000. Leading zeros, signs, fractions and overflow are invalid. Known terminal commands before count are invalid.
  • A room is exactly name x y. Its nonempty valid UTF-8 name has no Unicode whitespace or controls and does not start with L or #. Hyphens are allowed. Names compare bytewise and are case-sensitive.
  • Coordinates match optional + or - followed by one or more decimal digits and fit a signed 64-bit int. A 64-bit Go target is required. Duplicate coordinates are valid; room names cannot repeat.
  • Each terminal marker occurs once and binds to the next room, skipping comments/unknown commands. A second marker while pending, a repeat marker, a marker in link phase or pending marker at EOF is invalid. Start/end must be distinct.
  • A tunnel has no whitespace. Consider every hyphen split whose two substrings name existing rooms: exactly one split must match. Zero matches or multiple matches fail. This preserves hyphenated names without inventing a new delimiter. Reject self-links and canonical duplicate pairs, including reversed duplicates.
  • Once a link is accepted, room definitions are closed. A room after links is invalid. Missing required structure, bad field counts and unknown noncommand lines fail.

U + A · Cycles, disconnectedness and turns

Self-links are invalid, consistent with the source's error examples and badexample01. Ordinary cycles among distinct rooms are valid and search must terminate. Disconnected extra rooms are valid when a start-end route exists; an unreachable end is an invalid-data/no-route result.

Upstream usage shows a pipeline into rooms vacated that turn. The academy therefore validates turns as batches: derive sources from old state, account for all departures, then arrivals, checking ordinary occupancy at the next boundary. Token order does not change legality. One undirected tunnel use total still forbids opposite swaps. Cyclic rotations of three or more ants are batch-valid under this convention; they are unnecessary for optimum completion and no part of the planner relies on retaining them. End is absorbing in accepted academy schedules. Keeping an arrived ant at end is without loss because it frees nonterminal resources.

A · Exact planning and deterministic output

The taught method searches the first feasible deadline in [d,d+n-1], where d is BFS distance. Feasibility uses integral flow on a time-expanded graph with split room capacity, holdovers and shared tunnel-time gadgets. Same-side gadget traversals become waits. P09/P10 contain the correspondence and minimum-deadline proofs.

Canonicalize names and edges bytewise, insert model arcs in a documented stable order, extract unit trajectories in that order and assign ant IDs 1..n. Ant ID spelling is decimal [1-9][0-9]* without signs or leading zeros. Output only moved ants, ID-ascending within each turn, separated by one space. No trailing spaces, empty movement turns or extra diagnostics; every line ends LF. Independent correct solvers may select different optimum schedules. Repeated runs of one implementation must match bytes.

A · Resource envelope and honest limits

Default maxima are 10000 ants, 10000 rooms, 50000 tunnels, 200000 expanded vertices, 1000000 stored residual arcs, 4000000 stored ant-time position cells, 16 MiB formatted output and 240 seconds total planning time, in addition to input limits. Preflight checked count arithmetic and monitor work. Valid input may exceed the computation budget; report resource refusal separately, without claiming infeasibility or returning a heuristic labelled optimal. Successful runs remain exact.

Model upper counts at horizon T are 2(T+1)V+2TE vertices and (2T+1)V+5TE original arcs; residual storage doubles original arcs. Counts alone are not a total byte guarantee: adjacency headers, metadata, extraction and output also consume memory. Profile the actual implementation and document the measured envelope.

A · Bonus

The optional renderer writes a 2D animated GIF using standard Go image packages, with text legend and replay. Default dimensions are 320×240, four subframes per turn, 40-centisecond initial/final holds and turn duration. Maximum dimensions are 1280×720, frames 2000 and total stored pixels 50000000. Budget breaches fail explicitly; they do not silently omit turns. There is no required JavaScript, GUI library, external font package or 3D implementation.
