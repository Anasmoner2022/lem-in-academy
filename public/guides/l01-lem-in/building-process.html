CHAPTER 10 OF 17

Wire transcript and process outcomes

Make the executable contract match the curriculum contract exactly.

Before writing code

  1. What can safely be printed before optimization finishes?
  2. Where should an I/O error after partial output be reported?

Build in small passes

  1. Map typed invalid-data, usage/I/O and resource errors at one Execute boundary.
  2. Format accepted Echo, exactly one blank separator and ID-sorted movement lines.
  3. Check write errors and keep all diagnostics off successful stdout.

A grounded hint

Use a status-returning process adapter so tests can inspect stdout, stderr and status without calling os.Exit. main is only the final adapter.

Trace and self-check

Force a planner timeout with valid input. stdout must remain empty, stderr must identify resource exhaustion and exit must be 3.

Exit gate

Subprocess tests assert all stream and exit outcomes, including missing files and invalid argument counts.
