Verification and exit gates

One valid optimum, not an ID assignment oracle

For the supplied three-ant corridor, a valid four-turn suffix is:

L1-a
L1-t L2-a
L2-t L3-a
L3-t

Your deterministic extraction may assign IDs differently. The checker must still find four legal turns, all ants at end and valid output spelling. Compare exact bytes only across repeated runs of your own declared tie-breaking implementation.

Required evidence cases

  • Direct edge, n=3: three turns; two disjoint length-two branches, n=3: three turns.
  • P07 greedy trap, n=4: minimum five turns; a six-turn shortest-only answer fails optimality.
  • Ordinary cycle, disconnected extra room and nonnumeric unordered names: accepted when a route exists.
  • Every P03 grammar mutation and every P06 movement mutation: deliberately classified.
  • P11's 3294 tiny graph/ant cases: compare optimum and replay every returned plan; report all skips.
  • Source examples 00..05: audit ceilings 6,8,11,6,6,8 respectively. Treat ceilings as compatibility checks, not proof that every displayed upstream schedule is optimal.
  • Source examples 06/07 with 100/1000 ants: below 90/150 seconds on recorded hardware for audit readiness.
  • Same input 20 runs: identical output. Limits, cancellation and failing writers: no crash or false optimality claim.

Final exit gate

Source builds, tests and vet pass; acceptance tests are enabled; no TODO core stubs remain; dependency review is standard-library-only; every returned schedule is legal; exactness proof and independent tiny evidence agree; process and resource behavior are documented. Instructor review is required before claiming readiness. This hub does not mark learner completion.

Submission evidence

Remove each acceptance test's explicit skip only when you begin that feature. Add tests for the failure boundaries described here, run go test ./... and go vet ./..., then show a reviewer a failing test produced by one deliberate bug and the repaired result. Submit the commands, input, expected result and actual result. A reviewer must inspect tests as well as pass counts.

Completion: the guide does not assess you automatically. Every required behavior and component gate must be demonstrated before a learner or instructor records readiness.
