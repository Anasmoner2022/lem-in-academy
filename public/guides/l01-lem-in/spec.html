Full specification

Mandatory behavior

  1. Name the compiled CLI lem-in. Accept exactly one file argument. Read the colony from that file; stdin is not a substitute for the mandatory argument.
  2. Start n numbered ants at start and deliver all to end in the minimum number of movement turns. Each ant moves at most once per turn along one existing tunnel. Ordinary rooms hold at most one ant; start/end have unlimited occupancy. Each undirected tunnel is used once at most per turn.
  3. Accept room names, coordinates, commands and tunnels under the complete published grammar. Names are not assumed numeric or ordered. Coordinates are signed ints used only by the bonus. Ignore unknown commands semantically while retaining them in the accepted echo.
  4. Reject malformed counts, missing or duplicate terminals, duplicate rooms, invalid/overflowing coordinates, bad endpoint syntax, unknown endpoints, self-links, duplicate/reversed tunnels and no route. Ordinary cycles and disconnected extra rooms are valid if a start-end route remains.
  5. Use the exact P09/P10 method, or submit an alternative exact algorithm with a comparably complete correctness argument and independent evidence. A fixed greedy route set, maximum disjoint-path count alone, or one BFS path is insufficient.
  6. Success stdout is normalized accepted input with one final LF, one additional blank separator line, then nonempty movement lines. Tokens are L<ant>-<destination-name>, ascending ant ID within a turn, separated by one ASCII space and no trailing spaces. End the transcript with LF.
  7. Ant IDs are stable: canonicalize names/edges, use stable model arc insertion and unit extraction order, assign IDs 1..n by extraction. Multiple valid optima may differ between independently written solvers; repeated runs of one implementation must match exactly.
  8. Use the process stream and exit contract from P12. Invalid data/no route: stdout error prefix and exit 1, no echo. Usage/I/O: stderr and exit 2. Resource refusal: stderr and exit 3, no claimed plan. Success: exit 0.
  9. Keep assessed code standard-library-only. Include meaningful unit, integration, mutation and fuzz tests. Explain resource limits and all successful-run exactness guarantees. Publish performance evidence for the upstream audit examples before claiming audit readiness.

Academy additions and scope

The stricter numeric spelling, ambiguous hyphen resolution, whitespace/echo policy, simultaneous turn convention, ordering, streams, exits and budgets are academy policies. They are independently testable and may need adjustment if the local institution uses different interpretations. The GIF visualizer is a separate optional project after P13/P14. No GUI, browser JavaScript, third-party graph library or ready-made solver is required.
