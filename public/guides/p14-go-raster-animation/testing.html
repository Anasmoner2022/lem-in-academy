Verification and exit gates

  • Two snapshots with one moving dot produce six frames with delays [40,10,10,10,10,40].
  • All coordinates equal: centered scene without divide-by-zero.
  • Negative and near-int64-extreme coordinates: no integer overflow or nonfinite transform.
  • A line ending at an image boundary and a disc crossing padding: no out-of-bounds panic.
  • Decode the GIF back: dimensions, frame count, palette and delays are as declared.
  • Mutate one frame after rendering and verify another frame's pixels do not change.
  • Budget one pixel below the required total: resource error before frame allocation.

Exit gate

Inspect the first/last PNG and GIF in a viewer, verify no trails or missing endpoint frames and keep a text legend. Pixel/metadata tests and visual inspection serve different purposes.

Submission evidence

Remove each acceptance test's explicit skip only when you begin that feature. Add tests for the failure boundaries described here, run go test ./... and go vet ./..., then show a reviewer a failing test produced by one deliberate bug and the repaired result. Submit the commands, input, expected result and actual result. A reviewer must inspect tests as well as pass counts.

Completion: the guide does not assess you automatically. Every required behavior and component gate must be demonstrated before a learner or instructor records readiness.
