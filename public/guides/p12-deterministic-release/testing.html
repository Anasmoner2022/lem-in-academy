Verification and exit gates

For V=3,E=2,T=3, the upper counts are vertices=36 original_arcs=51 residual_arcs=102. Derive each count independently from the model.

  • V=2,E=1,T=1: 10 vertices, 11 original arcs, 22 residual arcs as an upper estimate; omitting end connector entries may reduce actual arcs.
  • Negative parameters and overflowing products: error before allocation.
  • Configured vertex budget 35 for the 36-vertex example: resource error, never infeasible.
  • Writer failure after a prefix: I/O exit and no appended invalid-data line.
  • Twenty identical runs produce exact byte equality.
  • Audit timing results remain pending until a completed solver is benchmarked on recorded hardware.

Exit gate

Explain every configured limit, its effect on valid but oversized input and why it cannot weaken the exactness claim for successful runs.

Submission evidence

Remove each acceptance test's explicit skip only when you begin that feature. Add tests for the failure boundaries described here, run go test ./... and go vet ./..., then show a reviewer a failing test produced by one deliberate bug and the repaired result. Submit the commands, input, expected result and actual result. A reviewer must inspect tests as well as pass counts.

Completion: the guide does not assess you automatically. Every required behavior and component gate must be demonstrated before a learner or instructor records readiness.
