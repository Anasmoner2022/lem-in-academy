Verification and exit gates

The fixture contains three turns, so expect 14 GIF frames at the configured four-subframe rate, with first/last holds of 40 centiseconds. All ants must end at t in replay.txt.

  • Corridor, two-branch colony, negative coordinates, zero-span axes and coincident rooms: all render without panic.
  • Hyphenated and UTF-8 names survive the legend; names need not fit inside a room marker.
  • Decode the output with gif.DecodeAll and compare frame dimensions, count, delays and final keyframe pixels.
  • Invalid solver output, truncated replay, bad move and resource breach: no final success artifact.
  • Existing output files without -overwrite: clear error and unchanged files.
  • Inspect real motion in a viewer; compare several logical boundaries with replay.txt, checking waits, terminal crowds and no trails.

Exit gate

Core L01 readiness remains separate. The optional bonus is review-ready only after a real pipeline, decode-back checks, failure cleanup tests and viewed animation pass. Record any untested shell/viewer combinations honestly.

Submission evidence

Remove each acceptance test's explicit skip only when you begin that feature. Add tests for the failure boundaries described here, run go test ./... and go vet ./..., then show a reviewer a failing test produced by one deliberate bug and the repaired result. Submit the commands, input, expected result and actual result. A reviewer must inspect tests as well as pass counts.

Completion: the guide does not assess you automatically. Every required behavior and component gate must be demonstrated before a learner or instructor records readiness.
