CHAPTER 6 OF 14

Build canonical adjacency

Turn names and undirected edges into a reproducible graph.

Before writing code

  1. What is a room's stable ID when input order changes?
  2. Why must an undirected edge create two adjacency entries?

Build in small passes

  1. Sort a copied list of names and build a name-to-ID dictionary.
  2. Validate endpoint identity and edge uniqueness.
  3. Allocate adjacency lists, append both directions and sort each list.

A grounded hint

Canonical ordering is a boundary decision. A later BFS can iterate arrays deterministically without repeatedly sorting names.

Trace and self-check

For names c,a,b and edges c-a,a-b, predict IDs a=0,b=1,c=2 and adjacency a:[b,c], b:[a], c:[a].

Exit gate

Reversing every edge endpoint and permuting input records leaves the inventory bytes unchanged.
