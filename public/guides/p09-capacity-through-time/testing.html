Verification and exit gates

  • s-a-t, n=2: T=2 max flow 1; T=3 max flow 2.
  • Direct s-t, n=3: T=2 max flow 2; T=3 max flow 3.
  • Two length-two disjoint branches, n=2: T=2 max flow 2, with both arriving at end together.
  • A stationary occupied ordinary room blocks another arrival even if incoming tunnels differ.
  • Both directional uses of one tunnel-time share the bottleneck.
  • A same-side gadget traversal is extracted as a wait and never printed as a self move.
  • Counts just above a configured network budget produce a resource error before allocation; this is not deadline infeasibility.

Exit gate

Provide an annotated tiny network, the two-way correctness argument and countertests that fail if room splitting or the shared bottleneck is removed.

Submission evidence

Remove each acceptance test's explicit skip only when you begin that feature. Add tests for the failure boundaries described here, run go test ./... and go vet ./..., then show a reviewer a failing test produced by one deliberate bug and the repaired result. Submit the commands, input, expected result and actual result. A reviewer must inspect tests as well as pass counts.

Completion: the guide does not assess you automatically. Every required behavior and component gate must be demonstrated before a learner or instructor records readiness.
