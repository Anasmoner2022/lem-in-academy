Verification and exit gates

Concrete cases

The supplied JSON fixture contains z at (1,0) and a at (-2,5). After implementation, go run . testdata/rooms.json prints:

a -2 5
z 1 0
  • []: success and zero output bytes.
  • Two rooms named a: validation error and no inventory.
  • A room named Lbad or an empty name: validation error.
  • [, a missing file, and two consecutive JSON arrays: distinct error paths without panic.
  • A writer returning an error: Run propagates it.

Exit gate

Explain why map order cannot define output order, why zero coordinates are valid and why a returned error must be checked. Show gofmt-clean files and tests that verify output bytes and lack of caller mutation.

Submission evidence

Remove each acceptance test's explicit skip only when you begin that feature. Add tests for the failure boundaries described here, run go test ./... and go vet ./..., then show a reviewer a failing test produced by one deliberate bug and the repaired result. Submit the commands, input, expected result and actual result. A reviewer must inspect tests as well as pass counts.

Completion: the guide does not assess you automatically. Every required behavior and component gate must be demonstrated before a learner or instructor records readiness.
