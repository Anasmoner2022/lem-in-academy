CHAPTER 4 OF 14

Full specification

  1. Implement a mutable Network with stable original-edge handles, adjacency lists and paired reverse indices. Reject negative capacities, invalid endpoints and source==sink. Zero capacity is allowed.
  2. Use BFS to find augmenting paths through positive residual arcs. Store parent arc identities, not merely parent vertices, because multiple arcs can share endpoints.
  3. Find a bottleneck, update forward and reverse residual capacities and repeat until no path or a supplied nonnegative target value is reached. Never augment beyond the remaining target.
  4. Return the achieved flow and permit extraction of original-edge flows. Repeated calls on the same residual state must have an explicitly documented meaning; this academy API resets from original capacities for each Solve call.
  5. Verify bounds 0≤f≤c and conservation. On exhausted runs, report a source-reachable cut and compare its capacity with value. Do not claim cut equality on an early target stop.
  6. Use integer capacities and checked additions. This engine uses O(V+E) storage. BFS augmentation has general O(VE²) worst-case cost; with target n and integral capacities, no more than n successful augmentations are needed, giving O(n(V+E)) for the capped task.
  7. The CLI JSON provides V, Arcs, Source, Sink and Target. The fixture's target is 2 and it prints flow=2. No room splitting or timetable logic yet.
