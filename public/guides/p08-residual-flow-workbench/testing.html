Verification and exit gates

  • Unit diamond s-a-t and s-b-t: target 2 achieves 2.
  • Capacity 2 into a followed by capacity 1 out: max flow 1 and exhausted cut 1.
  • No source-sink path: flow 0 without error; this is a feasible network with no throughput.
  • Forced initial s-a-b-t augmentation: residual cancellation permits value 2.
  • Antiparallel original arcs preserve separate identities and nonnegative residuals.
  • Target 1 on a capacity-2 network stops at 1 and makes no unjustified maximum-cut claim.
  • Negative capacity, invalid endpoints and integer overflow are rejected.

Exit gate

Demonstrate capacity bounds, conservation, integrality and a cut witness after exhaustion. Explain the target-capped complexity separately from the general Edmonds-Karp bound.

Submission evidence

Remove each acceptance test's explicit skip only when you begin that feature. Add tests for the failure boundaries described here, run go test ./... and go vet ./..., then show a reviewer a failing test produced by one deliberate bug and the repaired result. Submit the commands, input, expected result and actual result. A reviewer must inspect tests as well as pass counts.

Completion: the guide does not assess you automatically. Every required behavior and component gate must be demonstrated before a learner or instructor records readiness.
