Full specification

  1. Implement Step(g,start,end,positions,moves), where positions[i] is ant i+1's room. Validate the initial positions and all room IDs.
  2. For each intent, require ant in 1..n, at most one intent for that ant, an existing undirected tunnel and a different destination. An ant already at end cannot leave.
  3. Use a canonical unordered endpoint pair to ensure each tunnel is used at most once across both directions during the turn.
  4. Compute all departures and arrivals from the old state. A room vacated this turn may receive one ant. Reject two arrivals to the same ordinary room or an arrival into a stationary occupied room.
  5. Start and end permit multiple ants. Waiting is legal, but no empty movement turn is accepted in a completed canonical solution stream. The general Step API can validate an empty batch as unchanged state.
  6. Do not mutate positions or moves on either success or failure. Return next positions only after the entire batch passes.
  7. The CLI reads a JSON replay with a graph and turns, starts all ants at start, prints valid turns=T arrived=N only if all ants reach end. An incomplete replay is a distinct error.

The academy uses simultaneous turns with departures before arrivals. Cyclic rotations around three or more rooms are batch-valid under this convention; L01 can normalize closed per-turn movement cycles to waits before output. This choice is explicit because upstream does not fully define within-turn ordering.
