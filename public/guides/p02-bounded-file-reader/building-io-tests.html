CHAPTER 8 OF 14

Wire the CLI and fault tests

Prove that failures stay within the process contract.

Before writing code

  1. Who owns Close?
  2. Can stdout contain anything when input is rejected?

Build in small passes

  1. Validate argument count and open one path in Run.
  2. Build a complete numbered report only after ReadDocument succeeds.
  3. Test missing paths, argument errors and a failing Writer through injected boundaries.

A grounded hint

Keep the input file path out of the reader API. A pure Reader boundary makes short-read tests possible without filesystem tricks.

Trace and self-check

An oversized second line must fail before line 1 is written. Verify a zero-length output buffer on this path.

Exit gate

Record one valid file invocation, one usage failure and one failing-reader test without panic.
